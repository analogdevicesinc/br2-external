ADSP-SC598 Evaluation Kits

The SC598 evaluation kits pair the EV-SC598-SOM (Rev. E) with either the EV-SOMCRR-EZKIT or the EV-SOMCRR-EZLITE carrier board. The processor has one 1.2 GHz Cortex-A55 core and two 1 GHz SHARC DSP cores. Bare-metal or FreeRTOS applications for the SHARC cores can be loaded by Linux through remoteproc.

Build

From buildroot/, select the carrier board and apply the debug image fragments:

# EZ-KIT
make BR2_EXTERNAL="${PWD}/.." adi_sc598_ezkit_defconfig

# or EZLITE
make BR2_EXTERNAL="${PWD}/.." adi_sc598_ezlite_defconfig

support/kconfig/merge_config.sh .config \
    ../configs/buildroot.fragment \
    ../configs/debug.fragment
make -j$(nproc)

The build produces emmc.img and flash.img, the kernel Image, a FIT image, device trees for both carrier boards, U-Boot loaders, and the ext4/UBI root filesystem images in output/images/. The build output artifacts can be used to bootstrap the boards.

HTOL board

The SC598 HTOL (high-temperature operating life) board is a reliability-test fixture. It uses SPI flash rather than eMMC. It reuses the EV-SC598-SOM EZ-KIT defconfig with configs/htol.fragment, which selects the HTOL U-Boot configuration and applies its system settings.

The sc598-htol device tree is already included in the FIT image. Buildroot includes the device trees for all SC598 boards in that image, allowing one root filesystem image to support each board. To build an HTOL image locally, use the EZ-KIT defconfig and add ../configs/htol.fragment after the usual configuration fragments in the example above.

HTOL images are built on demand, not in the default CI matrix. In the Build ADI artifacts workflow, click Run workflow and enter:

  • defconfig: adi_sc598_ezkit_defconfig

  • flavor: debug htol

Each flavor names a Kconfig fragment in configs/. For a bootstrap image, use bootstrap htol. List htol last so its settings override earlier fragments.
